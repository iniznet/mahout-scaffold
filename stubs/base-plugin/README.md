# Howdah — a mahout starter plugin

The durable half of a WordPress site, as a starter. Content types, field groups, custom
tables, admin screens, REST routes and the migrations that build the schema — installed
once, and still there after a theme switch.

**Stack:** WordPress 7.1+ · PHP 8.4+ · Composer · PHPUnit · PHPStan max · Psalm (taint)
· Rector · PHP-CS-Fixer · Vite (build only)

Generated by `mahout-scaffold` (`mahout new <slug> --host=plugin`). `AGENTS.md` is the
working contract; it is the complete public one, and every rule in it is enforced by a
gate in this repository.

## Install

```bash
composer install            # the family resolves over VCS; no Packagist account needed
npm install && npm run build
```

Then activate the plugin. Activation runs the migrations that create the field tables,
which is the plugin's equivalent of the theme's `after_switch_theme` path — a plugin has
an activation hook, and mahout-db attaches its run to whichever one the host owns.

Before any gate will run, copy the test configuration:

```bash
cp tests/wp-tests-config.php.dist tests/wp-tests-config.php
```

## What lives here

| Path | Owns |
|---|---|
| `app/Bootstrap.php` | the composition root: every provider, named once, and the claim on the process |
| `app/Providers/` | hook attachment, assets, content registration, the field seam, the admin seam |
| `app/Features/<Name>/` | one vertical slice: schema, module, repository, mapper, data |
| `app/Components/` | typed props to markup — a block's render target, nothing else |
| `config/content-types.php` | the post types, taxonomies and REST routes this plugin registers |
| `config/fields.php` | the field groups and option screens, with a `StorageTarget` per field |
| `config/entries.php` | the Vite entry list |
| `uninstall.php` | the deletion policy, which is deliberately not a guess |

## Gates

```bash
composer check     # format, stan, psalm taint, arch, rector, test, hooks, i18n, config, doctor
```

`composer check` must pass before every commit. `composer doctor` asserts the
installation around this plugin as well as its own assembly, and it fails when a second
host on the same site also carries the packages: one process has one composition root
(mahout-kernel ADR-0007), so a theme that installs the family and a plugin that installs
the family are alternative assemblies, not two layers of one site.

## Choosing between this and the theme starter

The theme owns presentation: the template hierarchy, `theme.json`, design tokens,
navigation, and the Surfaces a request resolves to. This plugin owns what must survive
that being swapped. A site installs the packages in exactly one of them.
